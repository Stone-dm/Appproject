# 后端交付检查清单

2026-10-11 整理。以下是交付时需要重新核验的门槛，不是当前完成情况。迁移版本、测试数字、账号和证据须来自本次运行，不沿用历史报告。

## 每次交付先核验

- [ ] 记录提交版本、本次构建哈希，以及目标环境实际数据库迁移版本。
- [ ] 在专用验证环境执行迁移和模型一致性检查，确认迁移链完整。
- [ ] 执行后端正式测试，并记录命令、结果和失败项。
- [ ] 执行相应 Android 构建、单元测试和 Lint；在目标设备核验关键业务流程。
- [ ] 创作流程按 [验收指南](creation-demo-acceptance.md) 重新运行；记录失败、重试、断网、返回、刷新和账号切换结果。

## 业务与生产门槛

- [ ] 第 1 页完成端内学习闭环：阅读、预测、试炼、解释、迁移证据、创作、发布、评招、修订。
- [ ] 比赛展示路线具备真实内容、试炼规则、迁移任务和本次验收证据；路线范围以当前交付计划为准。
- [ ] 50 页内容逐页登记脚本、画面、文字层、审核版本、来源和端内结果。
- [ ] 正式环境使用 HTTPS、PostgreSQL、Redis、MinIO、ClamAV 和 Worker。
- [ ] 生产环境不使用 development image generator 或 development conference judge。
- [ ] 账号删除与匿名化完成 Worker 消费、事件终态、重试和保留规则的端到端验收，不能仅凭服务层测试登记完成。
- [ ] 内部审核和 Worker 身份完成最小权限隔离。
- [ ] 完成双账号大会闭环、生产依赖联调和签名 Release 验收。

## 证据存放

记录提交版本、迁移版本、构建哈希、测试命令、设备及账号类型、前置数据、操作结果和内容台账对应版本。运行证据统一进入 `artifacts/`；只按当次交付需要保留截图或录像，不把旧结果复制成新结论。

配置与测试入口见 [API 说明](../services/api/README.md) 和 [环境说明](../ENVIRONMENT.md)。
