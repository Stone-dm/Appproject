## 1. 项目目标与交付范围

### 1.1 产品定位

“机巧江湖”是以江湖主题呈现的学习与创作 Android 应用。主要业务包括账户与设置、课程/秘籍阅读、试炼和学习证据、创作对话及版本管理、媒体生成/上传、作品审核与分发、大会互动和个人行囊。

内容目录有十卷五十页的结构，但“存在 50 条目录内容”不等于每页都已经完成同等程度的画面、互动和验收。课程成熟度要结合实际页面和内容台账核对。

## 3. 系统架构与业务数据流

### 3.1 整体组织

客户端是原生 Android 单 `:app` 模块；后端是按业务域组织的模块化单体，API 与 Worker 可作为不同进程运行，但共用业务代码和数据库。

```text
Android Compose 页面
  -> ViewModel（页面状态、操作编排）
  -> Repository / API（登录态、业务读取、HTTP 请求）
  -> FastAPI 路由（请求验证、身份与权限）
  -> 领域服务（业务规则、事务、版本和状态变更）
  -> PostgreSQL（业务状态、后台任务事件）

Outbox Worker -> 读取数据库事件 -> 媒体、生成、导出、审核、删除等任务
Redis        -> 验证码、限流与缓存
MinIO        -> 上传隔离区、私有媒体和对象存储
ClamAV       -> 文件扫描
```

代码证据：[JianghuApp.kt](../../android/app/src/main/java/com/jueqiao/jianghu/JianghuApp.kt)、[API 入口](../../services/api/app/main.py)、[Worker](../../services/api/app/domains/media/worker.py)、[Compose 配置](../../infra/docker-compose.yml)。不要误以为后台任务使用的是一套独立微服务或 Redis 消息队列；当前 Worker 从数据库的 `OutboxEvent` 领取任务。

### 3.2 Android 结构

当前有 151 个生产 Kotlin 文件和 82 个页面目录。主要目录在 `android/app/src/main/java/com/jueqiao/jianghu/`：

- `JianghuApp.kt`：创建认证、设置和行囊仓库，手动依赖组装。
- `MainActivity.kt`、`nav/`：应用入口、路由常量和导航接线。
- `auth/`：认证 API、Repository、Token 存储。
- `creation/`、`conference/`、`distribution/`、`luggage/`：相关状态、数据模型和业务操作。
- `ui/screens/`：页面；部分按拼音、课程卷次/编号命名，编号不是可以直接删掉的旧版本号。
- `ui/components/`、`ui/theme/`：现有组件、布局和主题。
- `res/`：应用实际使用的图片、字体、字符串、Manifest 配套网络配置等。

创作与大会目前也使用 `LuggageRepository`，因此目录名称并不等于严格封闭的业务边界。不要只移动文件夹而不调整调用关系。

### 3.3 后端结构

`services/api/app/` 当前有 98 个 Python 文件：

- `main.py` 创建应用和共享依赖、注册路由。
- `api/routes/` 暴露 HTTP 路由；`core/` 放配置、安全、错误和中间件。
- `domains/` 有 11 个领域：`catalog`、`learning`、`creations`、`conference`、`distribution`、`luggage`、`mistakes`、`media`、`moderation`、`privacy`、`profiles`。
- 各领域通常通过 `contracts.py`、`service.py`、`models.py` 等划分请求契约、业务规则和存储模型，具体按现有代码组织。
- `services/` 等公共层保留认证、用户设置等逻辑；不是所有模块都已统一迁入 `domains/`。
- `db.py` 管理 SQLAlchemy 会话与缓存失效；`migrations/versions/` 保存完整 Alembic 升级链。

### 3.4 主要业务链路

- 学习：目录/秘籍详情 → 阅读事件 → 试炼 → 解释/迁移证据 → 进度与行囊聚合。
- 创作：创意/对话 → 工法 → 草图与版本 → 制作/工具调用 → 测试问题及修订 → 封卷 → 提交。
- 媒体：申请上传 → 隔离存储 → 完成上传 → Worker 扫描/处理 → 可授权访问的媒体。
- 发布：作品提交 → 审核 → 发布/分发；审核、申诉和撤回有独立状态。
- 大会：作品流、评语、采纳/改进、授权和切磋；具体门禁由服务端执行。

接口细节优先看 [API README](../../services/api/README.md) 链出的领域文档，以及 [OpenAPI 快照](../../services/api/docs/api/openapi.json)。快照可由 `scripts/export_openapi.py` 重新导出，修改接口后应同时核对测试与契约。

### 5.1 本次复现基线

### 5.2 一次性初始化

在交接根目录运行：

```powershell
py -3.13 handover/manage.py doctor
py -3.13 handover/manage.py setup
```

工具会创建主工程 `services/api/.venv`，优先从包内 `handover/wheels-win-py313/` 安装固定依赖，再以 editable 方式安装当前 API 源码。它会生成独立随机后端密钥，并尝试识别 Android SDK。

已有 `.env` 或 `local.properties` 不会被覆盖。需要改变服务地址或恢复自己的配置时手工编辑对应文件，禁止把他人的密钥直接复制到公共仓库。

## 6. 后端启动与数据库

### 6.1 先用离线源码验证开发环境

不需要 Docker，在根目录运行：

```powershell
py -3.13 handover/manage.py run-offline --port 8011
```

保持终端开启，访问 `http://127.0.0.1:8011/healthz` 与 `/offline-info` 检查状态。该路径执行离线适配源码，使用自身 `backend/app/` 副本；与主线 PostgreSQL 完整环境分开。

### 6.2 完整 Compose 服务栈

在完成配置初始化后进入 `Appproject/`：

```powershell
docker compose -f infra/docker-compose.yml config --quiet
docker compose -f infra/docker-compose.yml up -d --build
docker compose -f infra/docker-compose.yml ps
docker compose -f infra/docker-compose.yml logs --tail 100 api worker
```

API 容器启动命令会先执行 `alembic upgrade head`、种子导入，再启动 Uvicorn。ClamAV 首次就绪和镜像下载可能需要较长时间，不能只凭启动命令返回就认定所有服务已健康。

常用宿主机端口：API 8010、PostgreSQL 55432、Redis 16379、MinIO 19000/19001。服务间使用容器名称与内部端口。不要同时启动另一个占用 8010 的本地 Uvicorn。

`infra/docker-compose.override.yml` 配置了历史镜像镜像站；只有默认 Docker 镜像不可访问且确认该镜像站可用时再加这个文件，不把它当作必须依赖。

停止并保留数据：

```powershell
docker compose -f infra/docker-compose.yml down
```

不要随意添加 `-v`；它会删除 Compose 数据卷。已有环境先确认项目名、端口和卷，再运行迁移或重建操作。

### 6.3 本地 Python API/Worker

需要在 IDE 调试时，可以只运行 PostgreSQL、Redis、MinIO、ClamAV，然后在 `services/api/` 启动 API：

```powershell
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\python.exe -m app.domains.catalog.seed
.\.venv\Scripts\uvicorn.exe app.main:app --reload --port 8010
```

另开终端启动后台任务：

```powershell
.\.venv\Scripts\python.exe -m app.domains.media.worker
```

注意默认 Compose 没有向宿主机映射 ClamAV 3310，所以本地 Python 的真实扫描需要额外配置可达的 ClamAV，或使用完整容器服务。不要把开发扫描器冒充生产扫描。

### 6.4 数据库迁移与内容

迁移链当前有 26 个文件，末端为 `0026_video_media`。早期迁移仍是新库升级所需，不能当旧文件删除。运行环境的真实迁移状态用 `alembic current` / `alembic heads` 检查。

新模型变更需新增迁移、检查新库与已有数据升级、测试回归，不直接改旧迁移伪造状态。离线适配使用 `Base.metadata.create_all` 创建自己的测试数据库，不代表已经验证 PostgreSQL 迁移。

恢复历史备份应在独立数据库先检查，再决定如何升级；不要默认恢复进正在开发或生产运行的库。受限备份不附原来的加密密钥，部分加密字段可能无法解密，应与原负责人单独核对。

## 7. Android 构建和连接

### 7.1 主线 Debug

Android Studio 打开 `Appproject/android/`。终端构建可在根目录运行：

```powershell
py -3.13 handover/manage.py build-android --variant debug --java-home "C:/Program Files/Android/Android Studio/jbr"
```

该命令执行 Debug 构建、单元测试和 Lint。依赖已经下载时可加 `--offline`；首次接手没有 Gradle/Maven 缓存时不能使用离线模式。

输出是 `Appproject/android/app/build/outputs/apk/debug/app-debug.apk`。安装到设备由接手人选择目标，不自动覆盖他人的设备数据。

### 7.2 四种主线构建与独立离线构建

- `debug`：日常开发，读取本机 `AUTH_BASE_URL`。
- `release`：启用 R8 和资源压缩；正式签名及正式 HTTPS 服务仍需配置和验收。
- `demo`、`acceptance`：独立包名后缀，连接 8011 的演示/验收服务，使用 Debug 签名。
- `offline`：位于独立 `work/submission-local/android/` 工程，专用连接页、离线包名及网络配置；同样不是正式签名生产发行版。

### 7.3 地址设置

模拟器连接电脑主线 API：`AUTH_BASE_URL=http://10.0.2.2:8010/`。实体 USB 设备可配置 `http://127.0.0.1:8010/` 并执行：

```powershell
adb devices
adb -s <实际设备编号> reverse tcp:8010 tcp:8010
```

多设备时必须指定真实编号；拔插、重启或端口变化后重新核对。Compose 默认 MinIO 对外地址偏向模拟器访问；USB 或局域网设备还要同步调整媒体对外地址/端口映射，不能只改登录 API。

### 14.2 常见故障

- **端口占用**：先识别占用者，给本项目换端口；不要停止其他项目的数据库或服务。
